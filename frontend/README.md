# QOR AI — интерфейс команды Samgau

React + TypeScript + Vite. Изолированный модуль участника 3: интерфейс и демонстрация. Корневые файлы backend/Compose не изменяются.

## Быстрый старт

Из папки `frontend`:

```sh
npm ci
npm run dev
```

Открыть http://localhost:5173. По умолчанию доступно синтетическое демо из 12 SKU двух поставщиков. Ключи API не нужны. Шрифт включён в сборку; после установки зависимостей демо не требует внешнего доступа.

```sh
npm test
npm run build
npm run preview
```

Node.js 22 рекомендуется; точные зависимости зафиксированы в `package-lock.json`.

## Docker

```sh
docker compose -f frontend/compose.yaml up --build -d
```

Команда выполняется из корня репозитория. Открыть http://localhost:8080. Либо из `frontend`: `docker compose up --build -d`.

Образ многоэтапный: Node собирает статические файлы, Nginx обслуживает SPA. Для запуска нужен работающий Docker Engine. В Windows — Linux containers / WSL 2. На Mac ARM и сервере x86 собирать образ нативно на соответствующем хосте; `platform` намеренно не зафиксирован.

Контейнер не включает backend и не настраивает публичный HTTPS. Капитан подключает сервис `web` к общей Compose-сети с `api:8000`; Caddy завершает TLS перед ним. Для интеграции копируется определение сервиса с `build.context: ./frontend`. `/api/*` проксируется в `http://api:8000`, `/health` возвращает 200. Отсутствие backend не мешает запуску демо.

## Что готово

- Обзор с показателями, графиком запаса и сравнением сценариев.
- Таблица с поиском, фильтрами поставщика/риска, сортировкой и пагинацией.
- Паспорт решения: формула, история, график, факторы, ограничения и объяснение.
- Сценарии задержки поставок и изменения спроса с возвратом к исходному расчёту.
- API-вызов разбора свободного текста; в демо он явно отключён.
- Отчёт качества данных и блокировка заказа при неизвестном остатке.
- Проверка заказа отдельно по поставщикам, ручное количество с обязательной причиной, утверждение, CSV.
- Состояния загрузки, ошибки с повтором, отсутствие результатов, сетевой таймаут.
- Адаптивная навигация, управление диалогами с клавиатуры, возврат фокуса и reduced-motion.
- Встроенный сценарий демонстрации на 90 секунд.

## Подключение backend

Скопировать `.env.example` в `.env.local`. В Vite значение `VITE_DATA_MODE=api` устанавливает начальный режим; переключатель в UI остаётся доступен. `API_TARGET=http://localhost:8000` — цель dev-прокси. `VITE_API_BASE_URL` оставлять пустым для того же origin. Если задан внешний origin, указать его **без `/api`** и настроить CORS и cookies на backend.

**Никогда не помещать OpenAI/NVIDIA API-ключи в `VITE_*`.** Все вызовы провайдеров должны проходить через backend.

Контракт и примеры — [INTEGRATION.md](./INTEGRATION.md). Типы: `src/types.ts`. Сетевой адаптер: `src/lib/api.ts`. Демо-адаптер: `src/lib/demo.ts`.

API-режим не переключается на демоданные при ошибке. Ошибка сервера видна пользователю; переход на демо только явный. Реальные количества интерфейс не рассчитывает.

## Ограничения

- В этой ветке нет реального прогнозного движка, импортера Excel, LLM-сервиса, аутентификации или интеграции 1С. Это задачи остальных участников.
- Демо — модельные значения, включая названия и коды для показа формата. Это не анализ предоставленной компанией истории.
- Математика в `demo.ts` служит исключительно синтетическим UI-сценариям. Основной статистический алгоритм нельзя заменять этим адаптером.
- Демо-черновики живут в памяти вкладки до перезагрузки. В API-режиме сохранение, изоляция сессий, версии, MOQ и полномочия проверяет сервер.
- CSV демо экранирует формулы и сохраняет подтверждённые количества. Для API файл генерирует сервер; его безопасность и единицы — ответственность backend.
- Импорт через UI не реализован: backend предоставляет подготовленные наборы. Формат данных уже должен быть нормализован.
- API-адаптер собирает рекомендации страницами по 100, затем локально фильтрует и показывает по 6 строк. Ограничение — 20 000 SKU на расчёт; для больших наборов нужны серверные фильтры.
- Полноценная 3D-сцена отложена; в интерфейсе есть лёгкая CSS-иллюстрация поставки без дополнительных 3D-зависимостей.
- Публичная ссылка появляется после развёртывания капитаном на Linux-сервере.

## Демонстрация

1. Открыть обзор: синтетический набор обозначен на экране.
2. Нажать «Почему так?» или товар в таблице: показать формулу и выброс в истории.
3. Открыть «Сценарии», выбрать задержку +7 дней: риск и траектория изменятся. Количество может остаться прежним, если поставка всё ещё внутри горизонта.
4. Для наглядного изменения количества выбрать задержку +21 день: контрольная розетка изменится с 156 на 204 шт.
5. Нажать «Проверить и выгрузить», изменить количество и указать причину.
6. Утвердить черновик; скачать CSV для каждого поставщика.

## Проверки

`npm test` проверяет контрольные числа демо, задержки, отсутствие скрытого fallback в API, загрузку страниц рекомендаций, блокировку неизвестного остатка, требование утверждения, сохранение ручной правки и CSV-экранирование. Это проверки интерфейсного контракта, не валидация алгоритма команды.

Ручная проверка: поиск без результатов, фильтр «Проверить данные», сценарий, карточка объяснения, редактирование/утверждение/экспорт, ошибка подключения API, узкий экран. Перед сдачей повторить этот путь на развёрнутом сервере с готовым backend.
