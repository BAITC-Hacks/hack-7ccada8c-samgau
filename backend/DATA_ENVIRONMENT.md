# Окружение участника 2

Область работы по разделу 11 `MVP_SPEC_QOR_AI.md`: `app/engine`,
`app/importers` и соответствующие проверки алгоритма. Расчёт выполняется
без сетевых вызовов и не требует ключа ИИ. В этой подготовке алгоритм,
адаптеры импорта и общие контракты ещё не реализованы.

## Зависимости и установка

Для разработки выбран Python 3.12.12. Прямые зависимости перечислены
в `requirements-data.in`, полное дерево с точными версиями и хэшами —
в `requirements-data.lock`. Lock сформирован с `--universal`, включая
условные зависимости Windows; выполнение проверено на macOS ARM64.

| Библиотека | Назначение |
|---|---|
| pandas | Нормализация и агрегация таблиц |
| NumPy | Статистические вычисления |
| openpyxl | Чтение XLSX, включая потоковый режим больших файлов |
| Pydantic | Валидация нормализованных объектов |
| pytest | Контрольные проверки по разделу 13 ТЗ |

Из корня репозитория, при установленных Python 3.12.12 и uv:

```sh
uv venv backend/.venv --python 3.12.12
uv pip sync backend/requirements-data.lock --python backend/.venv/bin/python --require-hashes
uv pip check --python backend/.venv/bin/python
source backend/.venv/bin/activate
```

В Windows путь к Python окружения — `backend/.venv/Scripts/python.exe`,
активация PowerShell — `backend/.venv/Scripts/Activate.ps1`.
Локальное окружение создано для разработки; обязательный командный запуск
готового приложения по ТЗ — Docker Compose, который подключает капитан.

Обновление lock выполняется намеренно, после изменения зависимостей:

```sh
uv pip compile backend/requirements-data.in --python-version 3.12 --universal --generate-hashes --output-file backend/requirements-data.lock
```

## Переменные окружения

В корне подготовлены `.env.example` и локальный `.env`, исключённый из Git.
На этом компьютере `.env` имеет права `0600` и случайный `SESSION_SECRET`.
Для новой копии проекта нужно скопировать `.env.example` в `.env` и создать
собственный случайный секрет сессии. Ключи в примере всегда пустые.

Для OpenAI заполнить `OPENAI_API_KEY` и `OPENAI_MODEL`, оставив
`AI_PROVIDER=openai`. Для NVIDIA задать `AI_PROVIDER=nvidia`,
`NVIDIA_API_KEY`, `NVIDIA_MODEL` и `NVIDIA_BASE_URL` из доступного команде API.
Модель выбирается по фактическому доступу и проверяется капитаном по ТЗ;
в этом окружении сетевой вызов ИИ ещё не проверен.

`ADMIN_PASSWORD_HASH` оставлен пустым до определения капитаном способа
хэширования. Открытый пароль в это поле записывать нельзя.
`PUBLIC_BASE_URL` и `DATABASE_PATH` сейчас содержат локальные значения;
при сборке Compose капитан задаёт адрес приложения и путь внутри постоянного
volume. `DATA_MODE=synthetic` соответствует демонстрационному режиму ТЗ.

Файл `.env` сам по себе не подключает ИИ: его загрузку и проверку настроек
должны выполнять будущие серверная конфигурация или Compose.
Ключи используются только сервером. Локальные исходные файлы можно хранить
в исключённой из Git папке `data/`; разрешения на использование реальных
данных определяются разделами 7 и 15 ТЗ.

## Результаты проверки окружения

- Python окружения: 3.12.12; установлено 18 совместимых пакетов.
- Проверены импорты pandas, NumPy, openpyxl, Pydantic и запуск pytest.
- Проверено чтение синтетического XLSX: код `00123` остаётся строкой,
  отрицательное количество сохраняет знак, пустой остаток отличается от нуля.
- Проверены поля `.env`, режим synthetic, права файла и исключение из Git.
- Доступны Node 22.23.1, npm 10.9.8, Docker 29.0.1 и Compose 2.40.3.
- Docker Engine отвечает, архитектура контейнеров — Linux ARM64.

Исходные 12 Excel-файлов, код API/ИИ, интерфейс и Compose пока отсутствуют.
Их зависимости, запуск приложения, вызов ИИ, импорт реальных данных и
контрольные расчёты ещё не проверены. Linux AMD64 требует отдельной
проверки на целевом сервере. Проверки выше подтверждают только готовность
локальных библиотек к разработке части участника 2.
