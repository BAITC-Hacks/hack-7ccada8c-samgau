# Импорт участника 2

`IEKAdapter` и `SystemeElectricAdapter` используют общее ядро с явными схемами
`WorkbookMapping`. Поддержаны шесть типов источников каждого поставщика:
продажи, месячные продажи, месячные остатки, поставки в пути, сезонность и MOQ.
Готовые схемы относятся **только к синтетическим книгам**. Реальные файлы
не предоставлены; соответствие их многострочным шапкам не заявляется.

```python
from app.importers import IEKAdapter, ImportBatch, WorkbookMapping

mapping = WorkbookMapping(
    kind="sales", version="example-v1", sheet="Продажи", header_row=3,
    columns={"sku": "Код", "date": "Дата", "document_id": "Документ",
             "quantity": "Количество", "unit": "Ед.", "warehouse_id": "Склад"},
)
result = IEKAdapter().read("data/local/sales.xlsx", mapping)
batch = ImportBatch()
batch.add(result)
```

Заголовки совпадают точно. Для повторяющихся названий можно указать номер
колонки, начиная с 1. `header_row` и `skip_rows` задаются явно.
`defaults` задаёт подтверждённые оператором допущения и помечается как `assumed`.
Короткая дата `24.09` допустима только при заданном `short_date_year`.
Имя файла не определяет период продаж.

Для широких месячных таблиц используются `WideColumn(column=..., date=...)`.
Для широкого отчёта в пути те же поля задают даты поступлений и `shipment_id`.
Месячные остатки имеют явную семантику `month_start/month_end/unknown` и
не становятся актуальным наличием или точными интервалами stockout.
Расширенный отчёт в пути может дополнительно содержать снимок наличия:
`as_of`, `available` и/или `on_hand`, `reserved`, а также складскую `unit`.

`source_ref` каждой записи сохраняет файл, SHA-256, лист, строку, поле,
исходное и преобразованное значение. Формулы не исполняются; отсутствие
кэшированного результата даёт предупреждение. Пустоты остаются неизвестными.
Непригодная строка отражается в `rows_skipped` с причиной. Нулевой MOQ разрешён,
нулевая кратность превращается в неизвестное правило с предупреждением.

`ImportBatch` предотвращает повторное добавление того же SHA-256 для того же
поставщика и типа источника внутри набора. Капитан должен сохранять эти метаданные
в хранилище набора для идемпотентности между процессами и перезапусками.
После исправления схемы ошибочного импорта нужно построить новый нормализованный
набор, а не дописывать новые строки к старому.

`assemble_products` объединяет записи по поставщику, SKU и складу.
Отдельный MOQ-справочник приоритетнее правил в остальных отчётах, конфликт виден
в предупреждениях. Конфликтующие канонические записи, неоднозначные единицы,
неизвестная область склада или неполная сезонность требуют исправления входа.
Подтверждённый рост принимается только при `growth_semantics="percent_change"`;
иначе сохраняется предупреждение о неустановленном смысле.

Для сборки нужны явные политики поставщиков, соответствия категорий и сведения
о покрытии детализации/поступлений. Если строки продаж отклонены, заявление
о полном покрытии детализацией консервативно снимается для поставщика; при наличии
используются месячные итоги. Точные stockout-интервалы поступают отдельно.
Пример соединения всех источников — `import_demo_workbooks` в `demo_files.py`.
