# QOR AI — руководство по бэкенду капитана

Рабочий backend для интеграции команды: FastAPI, сессии, SQLite, HTTP API,
ИИ-адаптер, сценарии, черновики, утверждение и CSV. Контракт версии **1.0**.

**Это часть капитана.** Импорт 12 Excel и алгоритм спроса подключает участник 2.
`demo-platform-v1` — синтетический интеграционный пример с заранее заданными
прогнозами. Он проверяет API, но не доказывает выполнение требований по выбросам,
сезонности, росту и восстановлению спроса. В интерфейсе и API эта граница отмечена.

## Начните здесь

1. Распакуйте проект. Команды ниже выполняйте из папки с `run.py`.
2. Установите Python **3.12** и создайте виртуальное окружение.
3. Установите зависимости, запустите сервер, откройте `/api/docs`.
4. Передайте второму backend-разработчику `docs/INTEGRATION.md` и `backend/app/contracts.py`.
5. Передайте frontend-разработчику `docs/API.md`, `docs/openapi.json` и `examples/api-client.ts`.

### Ubuntu / Debian / macOS, включая macOS 11

При уже установленном Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.lock
cp .env.example .env
.venv/bin/python run.py
```

Если команда Python 3.12 у вас называется `python3`, используйте её после проверки
`python3 --version`. Системный Python Ubuntu/Debian может иметь другую версию;
не заменяйте его вручную. Для Debian/Ubuntu может требоваться пакет venv,
соответствующий установленному интерпретатору.

### Windows 10/11, PowerShell или cmd

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.lock
copy .env.example .env
.venv\Scripts\python.exe run.py
```

Активация окружения не нужна, политика выполнения PowerShell не мешает запуску.
Если нет `py`, используйте полный путь к установленному Python 3.12.

Открыть **http://127.0.0.1:8000/api/docs**. Ключ ИИ для запуска не требуется.
Для остановки — Ctrl+C. Данные сохраняются в `data/`.

### Что означает совместимость

| Платформа | Способ | Статус проверки этого пакета |
|---|---|---|
| Linux x86_64 с Python 3.12 | Прямой запуск | Тесты и реальный HTTP smoke выполнены в Linux-среде |
| Ubuntu / Debian | Python 3.12 или Docker Engine | Код переносим; отдельные установки этих дистрибутивов здесь не запускались |
| Windows 10/11 x64 | Python 3.12; Docker при поддерживаемой конфигурации | Шаблон CI добавлен, на Windows здесь не запускалось |
| macOS 11 | Прямой запуск Python 3.12 | Без обязательного Docker Desktop; на macOS 11 здесь не запускалось |
| Современная macOS Intel / Apple Silicon | Python 3.12 или поддерживаемый Docker | Шаблон CI добавлен; ARM-сборка здесь не запускалась |
| Любые старые Windows / 32 bit | Не заявлено | Не обещаем поддержку всех версий Windows |

Python-код не использует bash, PowerShell, Linux-пути или внешние CLI во время работы.
Совместимость всего приложения также зависит от библиотек участника 2.
Шаблон GitHub Actions проверяет Linux/Windows/macOS после включения по `docs/ci/README.md`,
но `macos-latest` не является проверкой именно macOS 11.

## Проверка за минуту

В другом терминале (из корня):

```bash
python scripts/smoke.py
```

Скрипт использует стандартную библиотеку и проверяет:
сессия → рекомендация 156 → сценарий 204 → ручная правка 168 → утверждение → CSV.
На Windows можно использовать `py -3.12 scripts/smoke.py`.

Автотесты, используя Python вашего `.venv`:

```bash
python -m pytest
python scripts/export_openapi.py
```

В командах `python` выше подразумевается интерпретатор виртуального окружения.
Точная команда Linux: `.venv/bin/python -m pytest`; Windows:
`.venv\Scripts\python.exe -m pytest`.

## Интерактивная проверка через Swagger

1. `POST /api/sessions` → скопировать поле `token`.
2. Нажать **Authorize** → вставить сам токен (без слова Bearer).
3. `POST /api/runs`:

```json
{
  "dataset_id": "demo-platform-v1",
  "supplier_id": "IEK",
  "as_of": "2026-09-22",
  "lead_time_days": 14,
  "review_days": 7,
  "safety_days": 7
}
```

4. С полученным `run_id` запросить рекомендации и карточку `0001_`.
5. Создать заказ с `skus: ["0001_"]`, утвердить с текущей `version` и
   `acknowledge_warnings: true`, затем скачать `export.csv`.

## Docker Compose

Нужны Docker Engine/поддерживаемый Docker Desktop и Compose v2.
Для macOS 11 используйте Python-маршрут выше: современный Docker Desktop
не является обещанным совместимым решением для этой старой ОС.

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps
python scripts/smoke.py --url http://localhost:8080
```

На Windows вместо `cp` допустимо `copy`.
Открыть **http://localhost:8080**. Остановить: `docker compose down`.
`down -v` удаляет базу и сертификаты — не используйте для обычного перезапуска.

Два контейнера: API и Caddy. API доступен только внутри Docker-сети.
SQLite и загрузки — в named volume, один процесс API, один worker.
Dockerfile работает от непривилегированного пользователя. Образы не используют `latest`.
Сборка выполняется нативно для архитектуры хоста; опубликованного multi-arch образа нет.
При объединении выполнены сборка Docker Compose и HTTP smoke через Caddy
в Linux x86_64. В шаблоне CI предусмотрены повторная сборка Compose и HTTP smoke.

## Подключение алгоритма и импортера

Полная инструкция: **docs/INTEGRATION.md**.

```dotenv
ENGINE_MODULE=app.engine.service
IMPORTER_MODULE=app.importers.service
```

Контракт: `import_dataset(ImportRequest) -> DatasetPayload` и
`calculate(DatasetPayload, CalculationParameters) -> EngineResult`.
Функции синхронные, без FastAPI/SQL/HTTP. Запросы проверяются Pydantic.
Результат допускается вернуть как модель или совместимый словарь.

Пока оба модуля не заданы, импорт возвращает **503 integration_missing**.
Нет подмены настоящего импорта демонстрационными расчётами.
Дополнительные библиотеки участник 2 фиксирует в `backend/requirements-engine.txt`.

## ИИ

Для фактического сетевого вызова заполните `.env`, выбрав доступную команде модель:

```dotenv
AI_PROVIDER=openai
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=ваш_ключ
AI_MODEL=идентификатор_доступной_модели
AI_RESPONSE_FORMAT=json_schema
```

Для NVIDIA: `AI_PROVIDER=nvidia`, адрес совместимого API и модель из вашего
кабинета; формат `json_object` можно выбрать при отсутствии JSON Schema.
Совместимость конкретной модели требует настоящего smoke-теста.

Перезапустить сервер, затем:

```bash
python scripts/ai_smoke.py --url http://127.0.0.1:8000
```

Этот тест должен получить `status: generated`. `fallback` означает, что
реальный ИИ-критерий ещё не выполнен. Он не выдаётся за успешную ИИ-интеграцию.
В поставленном пакете ключей нет; сетевой вызов провайдера здесь не выполнялся.

Роль ИИ: разобрать фразу в параметры или выбрать подтверждённые факторы объяснения.
Числа и итог заказа рассчитывает engine. Разбор фразы не применяет сценарий сам:
frontend показывает параметры и затем отдельно вызывает `/scenario`.
При ошибке/таймауте до 15 секунд остаются ручные поля и расчётное объяснение.
ИИ-объяснение ограничено выбором факторов; текст собирается сервером на русском,
включая запрос `kk`. Полная казахская локализация не реализована.

`ALLOW_REAL_AI=false` блокирует передачу реальных наборов провайдеру.
Включать только при разрешении владельца данных. Сырые файлы, история операций
и названия товаров не отправляются даже при включении; отправляется пакет факторов.

## Сессии и данные

- `POST /api/sessions` выдаёт непрозрачный Bearer-токен; сервер хранит его SHA-256.
- Срок сессии — 7 суток. При перезапуске токен и объекты сохраняются.
- Runs, imports и orders принадлежат сессии; чужие ID дают 404.
- Демо public доступно всем, импортированный набор — только создавшей сессии.
- Для импорта нужен дополнительный `X-Admin-Token`, заданный в `ADMIN_TOKEN`.
  Сгенерировать: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
- Админ-токен вводится отдельно в защищённом рабочем процессе, не зашивается в React.
- Это демонстрационные сессии без аккаунтов/восстановления доступа. Утрата токена
  означает утрату доступа из браузера. До окончания сессии выгрузите нужные заказы.
- После истечения токена данные автоматически не удаляются. Политику хранения
  и очистку должен определить владелец развёртывания.
- Одна фоновая задача импорта. После аварийного перезапуска незавершённая задача
  получает `interrupted`; тот же комплект можно загрузить повторно.
- До 12 XLSX/CSV и 64 MiB суммарно; ZIP надо распаковать локально.
- Повтор завершённого импорта того же комплекта/настроек в той же сессии
  возвращает прежний dataset, не удваивает историю.

## Черновики и CSV

Редактирование требует актуальную `version` и причину. Версия меняется атомарно.
Конкурирующее изменение даёт 409. Утверждённый снимок неизменяем;
для нового решения создайте новый run/черновик.

Сохраняются исходная рекомендация, правки, автор-сессия, время и подтверждение.
Неизвестные остатки/единицы, блокеры, нарушение MOQ/кратности блокируют утверждение.
Смена количества не исправляет отсутствующие исходные данные: нужен новый импорт
и расчёт после исправления владельцем данных.

CSV: UTF-8 с BOM, `;`, CRLF; фактически утверждённые количества.
Строки с признаками Excel-формул экранируются апострофом.
При импорте CSV в Excel задайте колонкам кодов тип «Текст»: CSV не управляет
автоматическим преобразованием числовых кодов с ведущими нулями в Excel.
Это табличный экспорт, не подтверждённая интеграция с конкретной 1С.
Отправка поставщику не выполняется.

## Подключение frontend

В dev: React/Vite на localhost:5173, API на 127.0.0.1:8000,
разрешённые origins задаются через `CORS_ORIGINS`.
В production: скопировать содержимое готового `frontend/dist/` в `deploy/web/`;
приложение использует относительный `/api`, Caddy сохраняет этот префикс.
Клиент в `examples/api-client.ts` не пересчитывает закупку и не содержит ключей ИИ.
