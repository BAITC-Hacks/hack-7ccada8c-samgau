# ИИ-помощник QOR

Раздел «ИИ-помощник» в меню: свободный вопрос, история текущего диалога, выбор товара, ссылки на разделы сайта и карточки товаров. Enter отправляет вопрос, Shift + Enter добавляет строку. Диалог живёт в памяти вкладки; смена расчёта или набора данных начинает новый диалог. Переход между разделами сохраняет текущий диалог.

## Подключение модели

В корневом `.env` задайте уже предусмотренные настройки сервера. Ключи не помещаются в `VITE_*`, код frontend или Git.

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=<ключ проекта>
OPENAI_MODEL=gpt-6-luna
AI_RESPONSE_FORMAT=json_schema
AI_TIMEOUT_SECONDS=35
# Для ответов по загруженным данным компании:
ALLOW_REAL_AI=true
```

OpenAI вызывается через `/v1/responses`, с JSON Schema, `store=false` и ограничением 4096 выходных токенов. Для GPT-5/GPT-6 установлен `reasoning.effort=low`. Исходящие запросы ограничены тайм-аутом, без автоматических повторов. Для NVIDIA сохранён `/chat/completions`: используйте `AI_PROVIDER=nvidia`, `NVIDIA_API_KEY`, `NVIDIA_MODEL` и `NVIDIA_BASE_URL` выбранного OpenAI-совместимого endpoint. Если модель поддерживает только JSON mode, задайте `AI_RESPONSE_FORMAT=json_object`. Ответ всё равно валидируется Pydantic. Общие `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL` имеют приоритет над переменными провайдера; оставьте их пустыми, если используете `OPENAI_*`.

После изменения настроек перезапустите API. Локально: `python run.py --host 127.0.0.1 --port 8000` (Python 3.12+, зависимости `backend/requirements-dev.lock` и `backend/requirements-engine.txt` в виртуальном окружении). Frontend: из `frontend` выполните `npm ci` и `npm run dev`. Vite проксирует `/api` на порт 8000. На Linux-сервере: `docker compose up -d --build`; корневой Compose собирает React и API, Caddy направляет `/api` на `api:8000`. Ключ нужно отдельно указать в `.env` сервера: Git его не переносит.

`GET /api/assistant/status` показывает готовность конфигурации, провайдера, название модели и разрешение на реальные данные. Наличие настроек не гарантирует доступность внешнего сервиса. Без ключа/модели, при тайм-ауте или невалидном ответе возвращается честно обозначенная **справка без ИИ**. Ошибка сопровождается безопасным `error_code`: неверный ключ, недоступная модель, исчерпанная квота, ограничение частоты, тайм-аут или отсутствие соединения. Исходный текст ошибки провайдера не передаётся в браузер: он может содержать секреты. Для временных сбоев доступна кнопка повтора. Свободные общие вопросы требуют работающей модели.

При `ALLOW_REAL_AI=false` снимки с `data_mode=real` не передаются внешней модели: доступна только локальная справка. Для работы с данными компании команда явно включает `ALLOW_REAL_AI=true` в серверной конфигурации.

## Контекст и ограничения MVP

- База знаний находится в `backend/app/ai/assistant.py`, словарь `KNOWLEDGE`: названия разделов, навигация, формула заказа, проверка данных и выгрузка CSV. Её нужно обновлять вместе с интерфейсом.
- `POST /api/assistant/messages` требует bearer-сессию из `/api/sessions`. Чат и расчётный клиент используют общую сессию вкладки. При 401 требуется обновить страницу; чат не создаёт новую сессию незаметно для пользователя и не читает чужие серверные расчёты.
- Контекст — **снимок текущего экрана, присланный браузером**, а не повторный расчёт или проверенная сервером запись. Передаются склад, дата, сводка, сценарий, выбранный товар и до 40 позиций с числовыми полями. Исходные Excel, история продаж, файлы и ключи не передаются. Вопросы, последние 12 сообщений и названия товаров входят в запрос к настроенному провайдеру.
- Артикулы, коды 1С из вопроса и выбранный товар имеют приоритет. В контексте есть исходная потребность, единицы запаса и заказа, коэффициент пересчёта, MOQ, шаг округления, до шести факторов, предупреждения и блокировки заказа. Неизвестные значения остаются `null`. При большом наборе список частичный; общие счётчики описывают весь расчёт. Для отсутствующего в контексте товара следует выбрать его в поле справа.
- Ответ модели содержит текст, `destinations` из разрешённого списка и `source_skus`. Несуществующие SKU и неизвестные разделы отклоняются. Ссылки открываются только после клика пользователя. Ответ отображается текстом, без исполнения HTML.
- Это консультационный текст: модель может ошибиться. Карточки источников показывают исходные значения текущего расчёта. Чат не применяет сценарии, не создаёт заказы, не утверждает закупки и не отправляет сообщения поставщикам.
- Лимиты: вопрос 2000 символов, история 12 сообщений, до 40 товаров, сериализованный запрос до 100000 символов, ожидание модели по умолчанию до 35 секунд (`AI_TIMEOUT_SECONDS`, допустимо 5–90), 10 обращений в минуту на сессию. История интерфейса ограничена 80 сообщениями. Интернет-поиска и векторной базы в MVP нет.

## Проверка

- `python -m pytest backend/tests -q`: 117 тестов прошли.
- `cd frontend` → `npm test`: 13 тестов прошли.
- `npm run build`: TypeScript/Vite собираются; остаётся предупреждение о размере JS bundle.
- 23.09.2026 выполнен `python scripts/ai_smoke.py` с реальным OpenAI `gpt-6-luna` на синтетическом наборе: сценарий, выбор факторов, ответ с правильным количеством, навигация к CSV, продолжение на казахском. Все ответы получили `status=generated`; справка не считается успехом. Расчёт после диалога не изменился.
- В браузере проверено объяснение кабеля: 480 м потребности → готовая рекомендация 2 бухты по 305 м, кнопка карточки товара и продолжение диалога о загрузке 1С. Автотесты отдельно проверяют отключение реальных данных, сохранение единиц и блокировок, ошибки квоты/ключа, усечённые ответы и совместимость NVIDIA.

Параметры запроса сверены с [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [документацией GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna). Самостоятельно проверьте доступность модели и квоту в проекте команды. Опубликованный в переписке ключ следует заменить; новый ключ хранится только в серверном `.env`.
